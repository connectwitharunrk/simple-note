  • Compose Multiplatform 1.11
  • Ktor 3.5

Before you start

Three things have to be installed. Everything else is fetched by the Gradle wrapper on first run.

Required

  • JDK 17 or newer — both projects target 17.
  • MySQL 8 or MariaDB 10.4+ — XAMPP includes MariaDB and phpMyAdmin.

Per platform

  • Desktop — nothing more. Start here.
  • Android — Android Studio, plus an emulator or a device.
  • iOS — Xcode, on a Mac.

The order below matters. The backend validates its schema against the database at startup and refuses to boot if the table is missing, and the client shows an error state until the backend answers.

Create the database

Run note-backend/db/schema.sql once. It creates the simple_note database and the notes table.

With phpMyAdmin

Start MySQL from the XAMPP control panel, open localhost/phpmyadmin, select the SQL tab, paste the contents of schema.sql and press Go.

From a terminal

shell 
$ mysql -u root -p < note-backend/db/schema.sql

Want something to look at on first launch? Load the sample notes too: db/seed.sql. It is safe to re-run — it clears the table first.

Why a script rather than automatic migration. The backend runs with ddl-auto=validate, so Hibernate never alters your tables. It compares the entity mapping against the real schema at startup and fails loudly if they have drifted apart.

Start the backend

shell 
$ cd note-backend
$ ./gradlew bootRun          # Windows: gradlew.bat bootRun

Wait for the line that confirms it is up:

output
Tomcat started on port 8080 (http) with context path '/'
Started NoteBackendApplicationKt in 7.517 seconds

Configuration

Every setting is an environment variable with a development default, so no credentials live in the source. The defaults match a stock XAMPP install.

VariableDefaultNotes
DB_URL jdbc:mariadb://localhost:3306/simple_note Plus ?connectionTimeZone=UTC&characterEncoding=utf8
DB_USERNAMEroot
DB_PASSWORDemptySet this for anything but local XAMPP
SERVER_PORT8080
shell 
$ DB_PASSWORD=secret ./gradlew bootRun

On a real MySQL server, change one variable. XAMPP ships MariaDB even though its control panel says “MySQL”, so the default URL uses the MariaDB driver. Both drivers are on the classpath and the URL scheme picks one:

DB_URL='jdbc:mysql://localhost:3306/simple_note?connectionTimeZone=UTC'

Run the client

One shared codebase, three entry points. Leave the backend running in its own terminal.

The quickest way to see the whole stack working, and the one to try first.

shell 
$ cd SimpleNote
$ ./gradlew :desktopApp:run

The window opens at 1100×760, wide enough for the two-pane layout: notes on the left, editor on the right. Drag it narrower than 840dp and it collapses to a single pane — the same behaviour a phone gets.

Build and run in one step

Start an emulator or connect a device with USB debugging enabled, then:

shell 
$ cd SimpleNote
$ ./gradlew :androidApp:installDebug

On an emulator this works with no further setup. On a physical device you must point the app at your machine’s LAN address — see Backend URL below.

Build an APK without installing

Useful for sharing a build or for CI:

shell 
# debug — installable straight away
$ ./gradlew :androidApp:assembleDebug

# release APK, and an App Bundle for Play
$ ./gradlew :androidApp:assembleRelease
$ ./gradlew :androidApp:bundleRelease

# everything at once
$ ./gradlew :androidApp:assemble

What each task leaves behind, under SimpleNote/androidApp/build/outputs/:

TaskOutputSize
assembleDebug apk/debug/androidApp-debug.apk 16 MB
assembleRelease apk/release/androidApp-release-unsigned.apk 12 MB
bundleRelease bundle/release/androidApp-release.aab 11 MB

Install an APK you have already built:

shell 
$ adb install -r androidApp/build/outputs/apk/debug/androidApp-debug.apk

Release builds are unsigned — the filename says so. This project has no signing config, so androidApp-release-unsigned.apk will not install on a device and the bundle cannot be uploaded to Play as-is.

To produce an installable release build, add a signingConfigs block to androidApp/build.gradle.kts and reference it from the release build type. Keep the keystore and its passwords out of version control — read them from environment variables or local.properties, the same way the backend reads its database credentials.

Clean rebuild

If a build starts behaving oddly after switching branches:

shell 
$ ./gradlew clean :androidApp:assembleDebug

Open the Xcode project and press Run:

shell 
$ open SimpleNote/iosApp/iosApp.xcodeproj

Not yet run on a device or simulator. This project was built on Windows. Both iOS targets compile and the source sets follow standard KMP conventions, but the app has never been launched — expect to fix small Xcode-side issues on the first build.

Pointing the client somewhere else

Each platform has a default that works for local development.

PlatformDefaultWhy
Android emulator http://10.0.2.2:8080 The emulator’s alias for your machine’s loopback. Inside the emulator, localhost is the emulated device itself.
iOS Simulator http://localhost:8080 The simulator shares the Mac’s network stack.
Desktop http://localhost:8080 Same machine.

To use a different server — a physical device on your Wi-Fi, or staging — pass a base URL when Koin starts:

kotlin 
initKoin(baseUrl = "http://192.168.1.20:8080")
PlatformEdit this file
AndroidandroidApp/…/NoteApplication.kt
DesktopdesktopApp/…/main.kt
iOSshared/src/iosMain/…/MainViewController.kt

A new address also needs permission to use plain HTTP. Both platforms block cleartext by default, and this app only opens it for local development hosts rather than switching it off globally. Add your LAN address to androidApp/src/main/res/xml/network_security_config.xml and to the NSExceptionDomains block in iosApp/iosApp/Info.plist.

Check it works

With the backend running, four requests confirm the whole path down to the database.

shell 
# create a note — expect 201 and a Location header
$ curl -i -X POST localhost:8080/api/notes \
    -H 'Content-Type: application/json' \
    -d '{"title":"Groceries","content":"Milk, eggs"}'

# list them — pinned first, then most recently updated
$ curl -s localhost:8080/api/notes

# search titles and content
$ curl -s 'localhost:8080/api/notes/search?query=milk'

# a missing note — expect 404 and the error envelope
$ curl -s localhost:8080/api/notes/9999

That last one should come back as:

json
{
  "status": 404,
  "error": "NOTE_NOT_FOUND",
  "message": "Note not found with id 9999",
  "path": "/api/notes/9999",
  "timestamp": "2026-08-14T09:53:56.800718400Z"
}

Check the app

Three interactions cover the editor, the list and the connection between them.

Do thisYou should see
Tap +, type a title, tap Save The editor closes and you are back on the list, with the new note at the top of the unpinned notes.
Open a note, change the text, tap Save The editor closes and the list shows the new text with a fresh “updated” timestamp.
Open a note, change the text, tap ✕ Discard changes? — choosing Discard leaves the note exactly as it was.

Saving always closes the editor, for a new note and an edited one alike, and only once the server has confirmed the write. If a save fails the editor stays open with your text still in it, so nothing you typed is lost to a dropped connection.

The ✕ appears only in the single-pane layout. Above 840dp the list is already beside the editor, so there is nothing to close back to — saving simply clears the right-hand pane.

Running the tests

Neither suite needs a running database or backend — the backend tests use in-memory H2, and the client tests mock the HTTP transport.

shell 
$ cd note-backend && ./gradlew test          # 84 tests
$ cd SimpleNote && ./gradlew :shared:jvmTest # 109 tests

./gradlew :shared:allTests runs the shared suite on every target your machine supports. On Windows and Linux, Gradle reports iosSimulatorArm64Test as disabled — simulator tests require macOS.

Troubleshooting

Every one of these came up while building the project.

The backend says port 8080 is already in use
Web server failed to start. Port 8080 was already in use.

Usually an earlier bootRun whose JVM outlived the Gradle daemon. Find it and stop it, or start on another port with SERVER_PORT=8081.

shell 
# Windows (PowerShell)
> Get-NetTCPConnection -LocalPort 8080 -State Listen |
    ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }

# macOS / Linux
$ lsof -ti:8080 | xargs kill -9
Hibernate thinks your database is MySQL 5.5.5
HHH000511: The 5.5.5 version for [org.hibernate.dialect.MySQLDialect] is no longer supported

You are on MariaDB but connecting with the MySQL driver. MariaDB reports its version as 5.5.5-10.4.32-MariaDB — that 5.5.5- prefix is a legacy compatibility hack, and Connector/J reads it as the actual version. Hibernate then generates SQL for a server from 2010.

Use a jdbc:mariadb:// URL instead. The driver is already on the classpath, and it is the default.

The backend won’t start because the schema doesn’t match
Schema-validation: missing table [notes]

Step 1 has not run, or it ran against a different database. Confirm the table exists and that DB_URL points at the same server phpMyAdmin is showing you.

shell 
$ mysql -u root -e "SHOW CREATE TABLE simple_note.notes\G"

This check is the point of ddl-auto=validate: it fails at startup rather than halfway through a request.

The Android app shows “Can’t reach the server”

Three things to check, in order:

Is the backend actually running? Load localhost:8080/api/notes in a browser on your machine first.

On an emulator, the address must be 10.0.2.2, not localhost. That is already the default.

On a physical device, both the base URL and network_security_config.xml need your machine’s LAN address, and the two devices must be on the same network. See Backend URL.

Gradle fails with a file lock after a cancelled build
java.io.IOException: Unable to delete directory … test-results

A killed test run can leave a JVM holding files open on Windows. Stop the daemons and remove the stale directory.

shell 
$ ./gradlew --stop
$ rm -rf shared/build/test-results
The first build takes several minutes

Expected. The Gradle wrapper downloads Gradle itself, then the Kotlin/Native toolchain for the iOS targets — several hundred megabytes on a cold cache. Later builds take seconds.
